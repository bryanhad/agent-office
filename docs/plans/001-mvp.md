# Plan 001: MVP (proof of concept)

Details referenced below live in [vision.md](../vision.md).

## Goal

Prove the core loop works end to end, with as little as possible. If this works, everything else is UI on top.

> I type a message in the browser → the backend runs it through the Agent SDK in my chosen project, on my subscription → the reply streams back into the chat → one blob in the office reflects what the agent is doing → when it wants to edit a file or run a command, I approve or deny it in the chat.

## In scope

1. **Backend**
   - Loads `CLAUDE_CODE_OAUTH_TOKEN` from `.env`, exits without it, strips competing credential variables (see vision.md, [Authentication](../vision.md#5-authentication-required)).
   - Config in `backend/.env`, all optional: `PORT` (default 3001), `WEB_PORT` (default 5173), `PROJECT_DIR` (see vision.md, [Project directory selection](../vision.md#6-project-directory-selection)), `MODEL` (main model; unset = account default). Real environment variables override `.env`.
   - `POST /api/project` takes a path, validates and resolves it (see vision.md, [Project directory selection](../vision.md#6-project-directory-selection)). Refused while the instance is pinned by `PROJECT_DIR`.
   - The backend tells the frontend which `PROJECT_DIR` case applies: not set, set and valid (pinned), or set but invalid (with the reason).
   - The WebSocket upgrade and `POST /api/project` check `Origin` (see vision.md, [Security](../vision.md#7-security)).
   - One Agent SDK session in that directory, using the options in [decision 009](../decisions/009-streaming-input-session.md). Follow-up messages continue the same session. SDK errors never crash the backend.
   - WebSocket that streams SDK events to the browser as small typed messages (e.g. `assistant_text`, `tool_use`, `permission_request`, `result`, `error`). Types live in `shared/`.
   - Permission requests are held until the browser answers approve or deny, survive a browser reload, and time out (see vision.md, [Pending permission requests](../vision.md#pending-permission-requests)).
   - Messages sent while the agent is busy wait in a backend queue and can be cancelled. A Stop control interrupts the turn and cancels queued messages and pending requests (see vision.md, [Chat panel](../vision.md#chat-panel)).
   - Survives a restart: the last SDK `session_id` and the chat log are persisted per project (keyed by the absolute path) under `~/.agent-office/`. On open the session is resumed (a fresh one, with a neutral chat line, if resume fails) and the chat is restored. A request that was pending comes back resolved "cancelled", and queued messages come back cancelled, so nothing is sent without me seeing it.
2. **Frontend**
   - Start screen: path input prefilled with `~/`. Shows an error if the path is invalid. Skipped when `PROJECT_DIR` is valid; shows the config warning when it's invalid.
   - Two-panel layout (see [`docs/design/layout.png`](../design/layout.png)).
   - **Left:** project name on the wall and **one blob (the manager)** with all five states (see vision.md, [Design](../vision.md#characters-mvp-blobs)), driven only by store state.
   - **Right:** chat with streaming text, compact tool activity lines, approve/deny cards, queued messages, and the Stop button (see vision.md, [Chat panel](../vision.md#chat-panel)).
   - A **New chat** control in the chat header that starts a fresh SDK session and an empty chat for the project (like `/clear`).

## Out of scope

Multiple agents, roles, `@` mentions, the live preview window, 3D, pixel art, the folder browser, recent projects, the `agent-office [dir]` CLI start, browsing or switching between past sessions, sounds, multiple projects in one instance (run several instances instead, see [decision 010](../decisions/010-one-project-per-instance.md)), Docker Compose, the model dropdown, the usage bar.

## Done when

- [ ] Backend refuses to start without `CLAUDE_CODE_OAUTH_TOKEN`.
- [ ] I can open `~/some/project`, and an invalid path shows an error.
- [ ] I send "what does this project do?" and get a streamed answer about that project.
- [ ] I ask for a small file change, see an approve card, approve it, and the file actually changes.
- [ ] Denying a request stops the change, and the agent says so.
- [ ] The blob visibly changes between thinking, working, waiting and idle during that flow, and shows error when something fails.
- [ ] The blob component reads only store state (no WebSocket or event logic inside it).
- [ ] A follow-up message remembers the earlier conversation.
- [ ] Reloading the browser while a permission request is pending shows the card again, and approving it still works.
- [ ] With `PROJECT_DIR` set to a valid folder, the app opens straight into the main screen.
- [ ] With `PROJECT_DIR` set to an invalid folder, the start screen shows the config warning and a manually entered path still works.
- [ ] Two instances with different `PORT`/`WEB_PORT`/`PROJECT_DIR` run side by side without interfering.
- [ ] A message sent while the agent is busy shows as queued and is delivered when the turn ends.
- [ ] A queued message can be cancelled with its button or Esc, and the agent never sees it.
- [ ] Stop interrupts the agent, cancels queued messages and pending permissions, and the blob goes idle.
- [ ] Restarting the backend restores the chat, and the agent remembers the conversation.
- [ ] After a restart, a card that was pending and messages that were queued come back as cancelled.
- [ ] New chat starts a fresh session with an empty chat.
